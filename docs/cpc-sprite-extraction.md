# Прямое извлечение спрайтов CPC

Локальная кассета `Fernando Martin Basket Master.cdt` запущена в MAME до
матча. Снимок RAM и трассировка штатного блиттера подтвердили самостоятельный
цветной банк CPC, без необходимости вырезать изображения из скриншота.

## Формат и адреса

| Область | Размер | Назначение |
|---|---:|---|
| `32C8..66F3` | 13356 | 78 последовательных записей спрайтов |
| `66F4..678F` | 156 | 78 относительных 16-битных указателей |
| вместе | **13512** | полный извлекаемый банк |

Запись начинается двумя байтами `height, width_in_cpc_bytes`. Далее идут
`height × width` байт CPC Mode 1, по четыре двухбитных пикселя в байте. Перо
0 прозрачно. Выбор кадра выполняет код `1BC0`, используя базу `32C8` и таблицу
`66F4`; цветной блиттер находится в `83F8`.

Порядок перьев подтверждён не по скриншоту, а кодом матча. Таблица `73B1`
содержит цвет рамки `14`, затем hardware inks `15,14,0B,07`: **ярко-синий,
чёрный, белый, pastel red**. Поэтому перо 0 одновременно является синим
фоном площадки и прозрачным значением в спрайтовом блиттере `83F8`.

Найденные размеры:

| Размер | Кадров |
|---|---:|
| 24×32 | 32 |
| 24×40 | 22 |
| 20×24 | 10 |
| 16×16 | 6 |
| 12×16 | 2 |
| 8×8 | 6 |

Основные кадры игроков имеют те же размеры `24×32` и `24×40`, что и текущий
банк MSX/V06. Для многих из них маска совпадает полностью или почти полностью.
CPC отличается цветом внутри силуэта. Малые кадры голов и мяча плотнее
обрезаны, а в CPC присутствуют три дополнительных объекта 8×8.

## Формат для Вектора

`tools/extract_cpc_sprites.py` также строит подготовленный ресурс:

```text
height, width_px
row 0: plane0[stride], plane1[stride]
row 1: plane0[stride], plane1[stride]
...
relative pointer table
```

Он занимает **13784 байта**. Маска не хранится: блиттер вычисляет её один раз
на байт как `~(plane0 | plane1)`. При публикации исходные CPC-перья
`1,2,3` переводятся в индексы Вектора `2,1,3` простой перестановкой двух
плоскостей; исходная маска сохраняется на время операции, поэтому CPC ink 1
действительно рисует непрозрачный чёрный пиксель. Если хранить маску третьим слоем, объём вырос бы
до 20520 байт.

## Воспроизведение

Дамп снимается скриптом `tools/cpc_capture_match.lua`. Он ускоряет кассету,
выбирает матч для одного игрока и на кадре 20000 сохраняет RAM по пути из
переменной `CPC_RAM_DUMP` (по умолчанию `/tmp/basket-cpc-match.ram`). Для
запуска нужен тот же ROM path MAME, который используется `tools/cpc_run.sh`.

После получения 64-КБ дампа:

```sh
python3 tools/extract_cpc_sprites.py /tmp/basket-cpc-match.ram \
  --v06-rom build/v06/basket.rom --out build/cpc/sprites
```

Результат включает исходный банк, подготовленный двухплоскостный банк,
отдельные PNG, монтажный лист и JSON с размерами и сравнением силуэтов.

## Привязка извлечённого банка к движку MSX

Прямой ресурс выше содержит исходные 78 записей CPC. Он не является
готовым размещением для координат MSX: головы CPC плотно обрезаны.
`tools/prepare_cpc_sprite_bank.py` размещает цветные пиксели на исходных
канвасах MSX по `cfg/cpc_sprite_layout.json`. Для восьми голов канвас снова
24×16; горизонтальные поля отличаются на 0, 4, 6 или 8 пикселей. Необходимые
сдвиги туловищ также измерены по маскам Executive. Цвет каждого непрозрачного
пикселя сохраняется; сборка запрещает обрезать его сдвигом.

В рабочий банк входят 75 индексов исходного движка. Три дополнительные
CPC-записи остаются в прямом извлечении. Подготовленный банк занимает
13980 байт, `415A..77F5`; таблица возвращается к `7760` и побайтово совпадает
с исходными относительными указателями MSX. Дополнительная память под
увеличенные канвасы не требуется. Прямая подстановка прежнего обрезанного
банка давала отделённую голову, особенно в правом направлении.
