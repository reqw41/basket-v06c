# Проверки перед рефакторингом

Запуск из корня проекта:

```sh
python3 tools/verify_refactor.py --profile full
```

Это проверка текущего четырёхцветного Z80-порта перед дальнейшей
оптимизацией или перекомпиляцией в 8080.

## Что делает запуск

1. Сохраняет рабочий ROM и полный SHA-256 до сборки.
2. Копирует исходники, ресурсы и инструменты в два новых изолированных каталога.
   Существующий `build/v06` не используется как источник результатов сборки.
3. Выполняет две чистые сборки. Оба ROM должны совпасть между собой и с рабочим.
4. Запускает проверки анализатора, Python-модели спрайтов, переноса процедур,
   графики повтора/HUD и клавиатурные сценарии 1P, 2P, броска, выхода и повтора.
5. Проверяет хеш и исход сценария в новых метаданных. Прямой вызов процедуры
   не засчитывается как интеграционный сценарий.
6. Проверяет, что исходники, внешний инструментарий и рабочий ROM не изменились
   во время прогона. Неисправный сценарий не останавливает остальные проверки.

Артефакты каждого запуска находятся в отдельном каталоге
`build/verification/<UTC-время>/`:

- `working-before.rom` — сохранённый рабочий образ;
- `report.md` — краткая таблица;
- `report.json` — команды, статусы, длительности, хеши, ошибки, ограничения;
- `logs/` — полные логи;
- `work-1/`, `work-2/` — исходники и результаты чистых сборок;
- свежие трассы — в `work-1/build/v06/`.

Рабочие ROM и трассы в исходном `build/v06` не перезаписываются.
Результаты не добавляются в Git автоматически. Каталоги сохраняются для аудита.
Для своего нового каталога: `--output <путь>`; существующий каталог запрещён.

## Статусы и коды возврата

| Статус | Код | Значение |
|---|---:|---|
| CHECKS_PASS | 0 | Все включённые проверки прошли, с указанными ограничениями покрытия |
| BASELINE_PASS | 0 | Прошёл сокращённый профиль; это не полная приёмка |
| FAIL | 1 | Сборки различаются или хотя бы одна проверка не прошла |
| ERROR | 2 | Недоступна зависимость, превышен лимит, нет метаданных или нарушена целостность |
| NOT_RUN | — | Проверка явно исключена профилем |

Сокращённый профиль:

```sh
python3 tools/verify_refactor.py --profile baseline
```

Он исключает только `match_1p_esc` и `match_replay`. Используется для фиксации
контрольной точки с известными ограничениями; полный прогон всё равно нужен,
чтобы эти ограничения задокументировать. Не заменять FAIL на PASS или XFAIL
ради успешного коммита. Лимит одной команды: `--timeout 180` (секунды).

Целевой бюджет памяти (этап 1, не раскладка ROM):

```sh
python3 tools/memory_budget_v06.py
python3 tools/test_memory_budget_v06.py
```

См. [memory-budget.md](memory-budget.md). `PASS`/`DEFICIT` декларации не
означают, что рабочий ROM уже переехал; `memory_layout` остаётся
`NOT_CHECKED`.

## Ограничения покрытия

- `sprite_model` — модель Python, а не исполнение спрайтовой процедуры ROM.
- `replay_graphics` проверяет прямые вызовы процедур, включая подготовленный
  повтор в живом матче; не доказывает штатное событие, запускающее повтор.
- `match_replay` проверяет естественный вход. Полное завершение, прерывание
  и последующее продолжение матча ещё требуют отдельных игровых сценариев.
- `match_1p_throw` пока подтверждает вход и обращения к обработчику кнопки,
  а не все варианты завершения броска.
- Нет автоматической визуальной оценки мерцания или качества звука.
- `memory_layout: NOT_CHECKED`: целевая карта памяти ещё не внедрена.
- Адреса в существующих тестах относятся к текущей раскладке. При переносах
  нужно обновлять адресные контракты тестов вместе с кодом, не ослабляя проверки.

## Зависимости

Нужны Python 3, Node.js, sjasm, vector06js с Z80-адаптером и z80dis.
Текущий сборщик ищет sjasm в соседних проектах `kvalley-v06c`/`spirits-v06c`.
Анализатор использует `~/projects/spirits-v06c/tools/vendor/z80dis.py`.
Эмулятор: `V06` либо `~/projects/vector06js`.
Их полные пути и хеши записываются в отчёт; зависимости не устанавливаются.

Для проверки переноса нужен исходный эталон
`build/v06/basket-etalon-54d6ee2d.rom`. Его копия помещается только в первый
изолированный каталог после чистой сборки и не участвует в получении ROM.

Регрессии самого инструмента:

```sh
python3 tools/test_verify_refactor.py
```

Они проверяют отказ при чужом хеше ROM, неверном режиме, отсутствии готового
матча, подмене игрового сценария вызовом процедуры, ошибке процесса и таймауте.
