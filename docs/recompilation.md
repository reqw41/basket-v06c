## Когда включать рекомпилятор

**Поздно.** Конвейер Spirits §0:

1. дизасм с round-trip;
2. раскладка Вектора (ещё Z80) + verify;
3. адаптер экрана/ввода/звука, врезки, **живой эталон Z80**;
4. профиль горячих `IX`/`IY` с этого эталона;
5. `recompile_i8080.py` → `src/i8080/game.asm`;
6. гейты pure i8080 + block_equiv против эталона Z80.

Адаптер сразу пишется в подмножестве i8080. Код игры до шага 5 — Z80.
Скармливать рекомпилятору не-round-trip дизасм или образ без эталона Z80 —
ложный путь.

## Вход и выход

| | |
|---|---|
| **вход** | дизасм в раскладке v06, метки на каждую команду, verify байт в байт |
| **выход** | **один** `game.asm` (слияние кусков: иначе `equ 0x….` стухнут) |
| **инструмент** | `tools/recompile_i8080.py` (spirits; форк сюда при иных сегментах) |
| **ассемблер** | тот же `zasm --8080`, что у адаптера |
| **карта** | `labels.json` → `G_xxxx` / `v06map.js` для врезок и стендов |

## Жёсткие правила (из журнала Spirits)

1. **ED раньше IX/IY** — голый `ED xx` на i8080 = трёхбайтовый CALL в никуда.
2. Нет `prof-z80.json` → рекомпилятор **падает** (не молча «всё холодное»).
3. `OVERLAP`: заглушка входа посреди команды **и** наведение ссылок;
   `unused` у `Z_*` в lst = баг (у Spirits стреляло только после шара).
4. `il_ldir` — полный **BC** (B=0,C=n и длины >255 обычны).
5. Смещение `(ix|iy+d)` — **со знаком**.
6. `INX`/`DCX` флагов не ставят — на этом держится дешёвая развёртка на месте.
7. Аудит Z после сдвигов/`adc hl` (`--audit`).
8. `ld a,r` → `il_rnd`; на гейтах ряд фиксировать в **обоих** образах через карту.
9. Врезка в байт внутри команды, ставшей развёрткой → `OPERAND_PATCH`, не
   `BYTE_TAB` по старому адресу.
10. Мёртвый код после `SCR_PATCH` считать с негативом: PC профиля ⊆ reachable;
    SMC в «мёртвое» → `KEEP`; ссылка на вырезанное ловится сборкой.
11. `PIN`/`FIXED` для данных, читаемых из байтов кода или по старшему байту
    страницы; ловить бисектом по потоку вызовов адаптера + хэшу плоскостей.
12. `block_equiv` — на **границах итераций**, не кадрах; плоскости отдельно;
    кадровые эффекты (пламя) исключать честно + негатив; «0 границ» = провал.
13. Стенды: адреса из карты; пара образ↔ядро; события, не кадры; негативный
    контроль у каждого гейта (pitfalls §6).

## Первая неделя — до рекомпиляции (pitfalls §8)

Без этого самый дорогой класс дефектов («не перенесли») не ловится:

1. карта чт/зп оригинала по всем страницам;
2. сверка полных дампов work RAM с поправкой на переезд;
3. указатели в данных по карте использования;
4. `trap_stale` с первого прогона новой раскладки;
5. потребители каждой заглушки VDP.

## Basket: статус (05.11)

- E1 дизасм: `tools/disasm_v06.py` → `disasm/v06/game.asm`, 4579 команд
  (10 057 из 14 129 байт), метка `Z_` на каждой, round-trip байт в байт
  (`--verify`, в `verify_refactor`). Входы: покрытие
  `tools/collect_exec_v06.js` + xref того же SHA + `tools/disasm_v06_entries.json`.
- E1b символы: 1652 операнда метками, 149 меток данных, `dw` для таблицы
  клавиш AE5D..AE75; исключение-константа A778 (88CDh).
- E2 профиль: `PROF_OUT=build/analysis/prof-z80.json node tools/collect_exec_v06.js`
  (итерация = 8554), 460 итераций.
- E3 форк `tools/recompile_i8080.py`: данные приколочены на своих адресах
  (адаптер ссылается на переменные игры), код ложится в бывшие участки
  кода и доказанно свободные зоны; ячейки рантайма 9300..931F. Добавлены
  `ld (nn),ix`, дальние `bit/res/set (ix+d)`, `ld (nn),sp`/`ld sp,(nn)`,
  `exx` (теневые ячейки), `ldi` с P/V для `jp pe`, `im`/`ld i,a` → ничего.
  RST 08/10/20/28/30 — под частые формы `(ix+d)` (свободны после soft VDP).
- Перевод: 1478 команд Z80; код 10 057 → 12 629 Б + рантайм 632 Б.
- Память (05.11): зеркальные кадры спрайтов — ссылки на исходные строки
  (`tools/pack_sprite_mirrors.py`, MIR_ROW, −2342 Б) вместо словарей строк;
  RST 00 — шестой слот под формы `(ix+d)`. Свободно под код 14 196 Б,
  игра ложится с запасом ~800 Б (последний кусок AB25..AC04 до ABF4).
- Адаптер целиком на i8080 (05.11): все модули собираются `sjasm --8080`,
  `tools/z80only_scan.py` = 0. IX/IY заменены курсорами в ячейках 0F01..
  (CFP_NEW/CFP_OLD, DR_PTR, BP_CUR/BP_OLD, PCC_RECT, NRM_RECT), DIRTY_RESTORE
  и BP_BOUNDS берут список в HL, публикация читает пары через POP под DI.
  Метки адаптера линкуются (`tools/link_labels.py`), модули текут без
  внутренних ORG; карта памяти следует за ними (`tools/sync_memory_map.py`).
  Рост за весь перевод +68 Б; такты на Z80-ядре: спрайт −3%, публикация +5%
  (`tools/bench_procs.js`).
- Обработчик прерывания игры (36F3) в переводе сохраняет il_tmp/il_tmp2/
  il_f/il_a (ISR_SAVE в рекомпиляторе).
- i8080-образ (05.11, bd207a1): `tools/build_i8080_rom.py` →
  `build/i8080/basket-i8080.rom`, воспроизводится в чистом дереве (входы
  рекомпиляции в `cfg/recompile/`). На i8080-ядре vector06js проходит
  заставку, меню и матч с повтором (`tools/run_i8080.js`); гейт
  `tools/block_equiv.js` (снимки на входах процедур из Z80-прогона,
  сравнение по модулю карты адресов, ряд LD A,R общий): 0 расхождений,
  разобранные исключения — в ACCEPT. Найдено и исправлено: adc/sbc hl
  портил A, `ld h|l,(ix+d)` на месте, провал в дыру адаптера, SMC в
  развёрнутый `bit` (3846, HAND), DI после EI в эмуляторе i8080-js.
- Скорость i8080: 142 итерации игры за 3000 кадров против 219 у Z80
  (~65%); 18% тактов — обвязка хелперов (ix+d), 3,5% — il_ldir. Дальше —
  этап 8 (оптимизация горячих (ix+d) и рантайма).
- Найдено попутно: `ld (D1BA),ix` в 3A21 (MSX D789) — манифест переноса
  пропустил форму с DD, писало в видеоплоскость; исправлено в сборщике
  (`fix_unrelocated`), место мёртвое.

Цветовая схема порта (2+2) на рекомпилятор почти не влияет, но съедает
плоскости и запас RAM под рост кода — учитывать в `v06-memory.md` до
раскладки (plan §C).
