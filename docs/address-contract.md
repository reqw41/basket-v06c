# Контракт абсолютных адресов (этап 3)

`tools/annotate_window_v06.py` строит привязанный к SHA каталог текущего окна
`84D0..B257`. Помимо процедур, строк, SMC и остаточных участков отчёт теперь
содержит каждый трёхбайтовый абсолютный операнд достижимого кода:

- адрес команды, opcode и целевой адрес;
- тип зависимости: call, jump, data address или stack pointer;
- класс цели: system, adapter, low data/state, game window, gfx/runtime buffer,
  D-region, stack или visible plane.

Отчёт `build/v06/window_entities.json` не объявляет холодные байты свободными.
`proven_dead_bytes` остаётся нулём; after-JP участки считаются только
кандидатами аудита. Полный актуальный xref даёт 10021 CFG-байт, 755 байт
явно удерживаемых данных, 35 SMC-сайтов и 634 остаточных байта, которые нельзя
освобождать без дополнительного доказательства.

Общий `verify_refactor.py` запускает этот инвентарь после игровых сценариев,
вкладывает его в `report.json` и проверяет SHA ROM. При фактическом переезде
этапа 6 этот список становится входом для relocation map и `trap_stale`.
