# Вектор-06Ц: режим 2+2 плоскости под цвет CPC

## Зачем

MSX Executive уже цветнее первой ч/б MSX-версии, но эталон «как на коробке
для глаз» у Dinamic-спортивных портов — **Amstrad CPC Mode 1 (4 пера)**.
На Векторе ближайший аппаратный аналог без трюков — работа в **двух
парах плоскостей** (2+2): четыре комбинации битов → четыре цвета
палитры, как четыре пера CPC.

Цель порта Basket: вытащить отрисовку в эту схему **с самого начала**, а
не «сначала моно, потом раскрасим» — иначе блиты и форматы спрайтов
придутся переписывать дважды.

## Модель CPC (эталон взгляда)

У Basket Master на CPC (лента `ref/cpc/Fernando Martin Basket Master.cdt`
из `basketmb.zip`):

- Mode 1: 320×200, **4 пера**
- пиксель = 2 бита, упакованные в байт экрана `C000..`
- графика игроков/мяча изначально часто 1-битная у семейства Dinamic;
  цвет даёт атрибутная/перьевая схема при выгрузке (как у Spirits CPC:
  теневой 1-бит + карта перьев → разворот в Mode 1)

Код локальной CPC-версии и игровой экран дают одну устойчивую схему:
**чёрный + ярко-синий + белый + лососево-розовый**. Синий занимает поле и
крупные плашки, белый оставляет разметку, текст и форму читаемыми, розовый
выделяет кожу и часть цифр/индикаторов.

В исходной CPC-таблице матча по адресу `73B1` после цвета рамки лежат
hardware inks `15,14,0B,07`: source pen 0 — ярко-синий, 1 — чёрный,
2 — белый, 3 — pastel red. Блиттер `83F8` считает source pen 0 прозрачным.

## Зафиксированные перья Вектора

Плоскость `E000` имеет вес 1, активная `C000` — вес 2. Индексы позволяют
оставлять однобитные фоновые элементы белыми и добавлять цвет спрайтам:

| C000:E000 | индекс | роль CPC | байт Вектора `BB GGG RRR` |
|---|---:|---|---:|
| `0:0` | 0 | ярко-синий фон/плашки | `C0` |
| `0:1` | 1 | белая графика/текст | `FF` |
| `1:0` | 2 | чёрный фон | `00` |
| `1:1` | 3 | тёплый розовый/кожа | `5F` |

`5F` — ближайший тёплый вариант ограниченного ЦАП Вектора к CPC pastel
red. Целевая таблица в `cfg/cpc_palette.json` повторяет эти четыре значения
четыре раза: неиспользуемые старшие плоскости не меняют выбранное перо.

Практическое следствие: синяя зона имеет оба бита равными нулю, белая линия
устанавливает только `E`, чёрный пиксель — только `C`, а розовый — оба бита.
Такой порядок позволяет выводить CPC-спрайт прямой перестановкой его двух
исходных плоскостей без покомпонентного перевода каждого пикселя.

## Модель Вектора

Классическая видеопамять Вектора — четыре битовые плоскости. Режим
отображения и приоритет задаются регистром границ/палитры; для порта
фиксируем контракт адаптера:

| логический слой | плоскости | роль |
|---|---|---|
| bit0 | `E000..FFFF` | младший бит «пера», действующая белая графика |
| bit1 | `C000..DFFF` | старший бит: чёрные и розовые пиксели |
| (пара 2) | плоскости C+D | либо вторая страница/HUD, либо выключены |

Физические базы зафиксированы целевой картой. `C000..DFFF` освобождён от
кода и обычных данных, обнулён в ROM и используется как старший цветовой
бит. `PAL_WRITE` активирует таблицу `C0,FF,00,5F`; тесты запрещают исполнение
из видеоплоскости, но разрешают её чтение и запись рендереру и повтору.

Итого на пиксель: значение `0..3` → индекс в 16-цветной палитре Вектора
(выбираем 4 из 16 под площадку/форму/мяч/фон).

## Стратегия вывода

1. CPC-спрайт хранится сразу как пара исходных битовых строк без отдельной маски.
2. `COLOR_SPRITE` вычисляет прозрачность как `~(plane0|plane1)` и меняет
   исходные плоскости местами. Source pens `1,2,3` становятся индексами
   Вектора `2,1,3`; непрозрачный чёрный сохраняется без отдельной таблицы.
3. Варианты сдвига 0/2/4/6 пикселей и клиппинг проверяются попиксельной
   эталонной моделью.
4. Повтор захватывает и удваивает обе плоскости, поэтому цвет не теряется.
5. Площадка и HUD используют ту же итоговую четвёрку ролей: синее поле и
   рамки, чёрные плашки, белая разметка и текст, salmon для зрителей.

## Анти-паттерны

- Рисовать «ZX ink/paper» в одной плоскости и надеяться докрасить позже.
- Хранить цвет только в MSX VDP-регистрах без собственной карты перьев —
  на Векторе VDP нет.
- Использовать все 4 плоскости как 16 цветов на пиксель для этой игры:
  дороже по fillrate и дальше от CPC-референса.

## Открытые вопросы (закрыть на этапе 3–5)

- [x] CPC-оформление: чёрный, ярко-синий, белый, лососево-розовый.
- [x] Executive MSX: SCREEN 2, таблица цветов пишется **постоянно**
      (`smoke --vramlog`, 3000 кадров: 64.6 тыс. записей, в матче ≈5 на кадр,
      всплески по 7 тыс. на смене экрана). Писатели D2A9, A1A4, D521, D8D1.
      Значения почти все «цвет на чёрном»: F1 11 17 1F 81 A1 51 41 71 91
      (+1A). Фон = чёрный → перо 0, шаблон читается обратно как A|B.
- [x] Прямого 2+2 хватает: предыдущие прямоугольники восстанавливаются
      отдельно в обеих плоскостях.
- [x] Перекрытия сохраняют порядок через одинаковую производную маску.
