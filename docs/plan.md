# План порта: Basket Master Executive → Вектор-06Ц

Порядок этапов — **как в Spirits**, не «сразу i8080». Источники:

- [`spirits-v06c/docs/recompilation.md`](../../spirits-v06c/docs/recompilation.md) — конвейер и гейты
- [`spirits-v06c/docs/pitfalls.md`](../../spirits-v06c/docs/pitfalls.md) — что ловить с первой недели
- сжатый чеклист — [recompilation.md](recompilation.md) здесь

Рекомпиляция Z80→i8080 — **последний крупный шаг кода игры**, после
живого эталона Z80 на Векторе. Адаптер пишется в i8080 сразу; игра до
этого шага остаётся Z80.

---

## Цель

Играбельный порт на ванильный Вектор (КР580ВМ80А). База — **MSX
Executive**. Картинка — **2+2 плоскости** (4 пера ≈ CPC Mode 1), решение
цвета **до** блитов. CPC — эталон взгляда и палитры, не база кода.

---

## Конвейер (обязательный порядок)

```
ref/msx (Executive)          манифест SHA, payload, entry
        │
        ▼
disasm round-trip            метки + символьные операнды (вход рекомпилятора!)
        │
        ▼
карта памяти оригинала       + инвентаризация чт/зп (§8 pitfalls) ← НЕ ОТКЛАДЫВАТЬ
        │
        ▼
раскладка v06 + verify       доказанный переезд; trap_stale с первого прогона
        │
        ▼
адаптер Z80-образа           экран 2+2, ввод, звук; врезки в BIOS/VDP
        │
        ▼
эталон Z80 на Векторе        playthrough / сверка состояния с живым MSX
        │
        ▼
профиль IX/IY                prof-z80.json с ЭТАЛОНА (иначе рекомпилятор падает)
        │
        ▼
recompile_i8080.py           один game.asm; labels.json; OVERLAP/PIN/FIXED/dead
        │
        ▼
гейты i8080                  check_i8080, block_equiv на ГРАНИЦАХ ИТЕРАЦИЙ,
                             негативные контроли; затем Emu80/MiSTer
```

## Этапы

### A. Intake и дизасм (до любой раскладки Вектора)

- [x] дамп **Executive** в `ref/msx/` + `MANIFEST.md` (не первая сырая MSX)
- [x] извлечь payload(ы), BLOAD/entry, сегменты
- [x] генератор дизасма → round-trip байт в байт (`zasm`)

не байты образа (`recompilation.md` §1 Spirits).

- [x] повтор шёл ≈23 с против ≈9 с на MSX (шаг ≈80 кадров: 28 —

      счёта 4): писал только нижнюю плоскость поверх CPC-трибун (розовый

- [ ] пока штамп активен, восстановление фона под игроком у трибун

### A.2 Отказ от MSX-вывода (решение 04.11: вывод только прямой, без soft VDP)

Живая трасса RST 08/10/20/28 (сиды 4242, 777; 8000 кадров) — кто ещё ходит
через эмуляцию портов 98h/99h:

- [x] M1. Штамп «вставших»: MSX-картинка B338 (ч/б) → CPC-штамп (CPC 2182:
      21×32 байта mode 1 из 264A в рабочий фон A568, смещения 0B и 20h).
      Штамп меняет фон: стирание за игроком (1AC0) берёт вставших; полная
      перерисовка корта возвращает сидячих. Место — 77F6..7AE7 (MSX-графика
      табло, читает только AFC8). Сделано 04.11: все фоновые выборки матча
      идут через BG_FETCH (B338) — 1AC0, 7B1F, шторка 184A; буфер пары
      игроков дописывает ячейки штампа после 8495 (STAMP_FILL_ROW, под EI).
      Детектор (полный корт, эталон сидячих/вставших): 0 из ~1180 выводов
- [x] M2. Табло при входе в матч: AFC8 рисует MSX-табло блиттером D252 поверх
      меню построчно; HUD_DECOR потом рисует CPC-табло. Вызов AFC8 убрать
- [x] M3. Табло (04.11): (а) полоса силы 9F48 писала только нижнюю
      плоскость → розовые чёрточки, остальное терялось; теперь обе плоскости,
      сплошная белая на синем (у CPC синяя на белом — у нас табло инверсное),
      HUD_TEXT_REFRESH перерисовывает её (9F25); (б) значок «мяч у команды»
      8AAE (MSX 7750/7758 через D252 — у нас в адреса ≥1800h, не виден) →
      CPC-спрайты 72/73 прямым выводом (HUD_ICON B455); (в) подпись TIME как
      у CPC; (г) цвет текста 91h (горящие фолы 9FC0, «BASKET !») — розовый
- [x] M4. Шторка после попадания A0BF/A132: OUT 99h/98h → прямой вывод столбцов
      (04.11: A0D0 на месте копирует столбец из BG_FETCH в обе плоскости;
      A132 — MSX-«занавес» только таблицей цветов — RET)
- [x] M5. VRAM-блиттер D252 (34BD..352A: D241/D247/D24C/D252; A775 заставка
      и данк, A62E) — все его записи уходили в отбрасываемые адреса ≥1800h;
      тело заменено сдвигом указателя 3302, как делал блиттер. Ветки в буфер
      ОЗУ (3530..) не тронуты. Попутно: A75F восстанавливал свой патч MSX-
      словом 88CDh (не перенесено) → блиттер звал 3488 и исполнял строку
      «DiNaMiC» как код; теперь 34DF — только ячейка-флаг (04.11)
- [x] M6. ISR 36F5: статус VDP → LD A,80h (вход только по кадровому IRQ);
      35C1 — чтение статуса убрано; запись R1 (3760) → RET (04.11)
- [x] M7. RST 08/10/20/28 → RET, SOFTVDP_* и SET_VBLANK удалены, мёртвые MSX-тела
      обнулены; гейт inventory_softvdp_v06.py (04.11, docs/softvdp-inventory.md).
      VRAM_TO_PLANE остаётся как пересчёт координат знакоместа в адрес плоскости
- [x] шумовые блоки на кольцах и игроках (на прогоне — перед фолом
      «DOUBLE»): ORPHAN_PREFIX_RESTORE (1480) звал DIRTY_RESTORE и терял HL —
      указатель потока стадии B498, публикация брала байты корта (29E7..)
      как спрайты. Срабатывало, когда префикс старого списка длиннее нового
      (мяч ушёл, поза фола одним спрайтом 4×40). HL сохраняется (04.11)
- [x] шум AY (04.11): удар мяча = тон B + шум (R6=31, A8). Сначала —
      случайные делители на свободных счётчиках ВИ53 (на слух «так себе»).
      Теперь спикер: ожидание кадрового импульса перед публикацией (B182 и
      COLOR_FRAME_END) заменено на NOISE_WAIT (152F). Пока SND_NOISE_SCAN
      видит шум, 8-битный LFSR идёт на PC0 через BSR порта 00 с частотой
      ≈3,6 кГц (1569) до следующего IRQ. Стоит 0 тактов кадра; шум звучит
      ≈10 % времени кадра (пачки по 50 Гц). Тон остаётся на ВИ53
- [x] следы мяча и игроков на полу, «призраки» после попадания (04.11).
      Детектор: сразу после каждой публикации весь пол вне текущих
      прямоугольников сравнивается с expected_court_pairs. Было 107 из 239
      испорченных публикаций, стало 0 из 480/359/422 на трёх вариантах
      ввода. Причины:
      1. NORMALIZE_FIND_PAIR (0B10) переносил одну пару игроков, и при
         [P1 P2 кольца] выходило [P2 P1 кольца]. BUFFER_PLAYERS брал кольца
         за пару, объединение 30×60 не помещалось, стирания не было. Теперь
         ищется пара игрока (высоты частей различны), за которой идут
         не-игроки, а 17E4 возвращается в 1AD0, пока переносить нечего.
      2. Шторка A0BF после попадания писала только нижний бит
         (COURT_TILE_WRITE → rst 8): верхние биты игроков оставались
         тёмными силуэтами. COURT_PAIR_OUT (1748) пишет обе плоскости.
      3. ORPHAN_PREFIX_RESTORE считал последние 4 записи игроками и при
         5 объектах (поза фола) стирал кольцо вместо ног. Теперь при 6/8
         считаются префиксы, иначе полные длины.
      4. Пропуск неизменённого объекта пропускал и стирание старого
         прямоугольника с тем же индексом, а после сдвига списка там стоял
         игрок. SKIP_OLD_RESTORE (14E7 → 0A04 → 1A52) стирает его с полной
         защитой, если прямоугольник другой.
      5. CSPR_META_STAGE ставил старой записи «без изменений» по номеру слота
         игры, а старый список сохранён после 1AD0. Теперь пометка ставится,
         только если столбец и строка совпадают
- [ ] в ч/б увеличенные полутона (точечные узоры) выглядят полосами: на MSX их
      гасит таблица цветов → см. пункт про таблицу цветов
- [ ] ч/б с учётом таблицы цветов (сейчас выводятся только биты шаблона)

### D. Адаптер на эталоне Z80 (рекомпиляции ещё нет)

Пишется в подмножестве i8080; врезки в **адреса Z80**-раскладки.

- [ ] схема **2+2** зафиксирована контрактом (см. [v06-planes-2plus2.md](v06-planes-2plus2.md)):
      1-битная логика игры + цвет на выгрузке в пару плоскостей
- [ ] таблицы врезок `JP_TAB`/`CALL_TAB`/`BYTE_TAB` (как `SCR_PATCH`)
- [ ] ввод → тень матрицы MSX; звук → ВИ53
- [ ] палитра **не** каждый кадр (полоса на железе)
- [ ] счётчик исполнений каждой врезки/заглушки на длинном прогоне
- [ ] сверка с живым MSX по **состоянию** (переменные, буферы), не только
      картинке; расписание стендов — по **событиям/итерациям**, не кадрам

Критерий выхода из D: эталон `*-z80.rom` (или без суффикса) стартует,
матч 1P/2P, stale=0, playthrough зелёный. Только тогда — E.

### E. Рекомпиляция Z80 → i8080

Вход: `disasm/.../v06/*.asm` после verify. Выход: один `src/i8080/game.asm`
(слияние кусков обязательно — межфайловые `equ` иначе стухнут).

- [ ] профиль `prof-z80.json` с эталона; без него — падать, не `PROF=none`
      по умолчанию
- [ ] порядок правил: **ED раньше IX/IY**
- [ ] горячие `(ix|iy+d)` на месте, холодные — `il_*`; смещение со знаком
- [ ] `il_ldir` на полном BC (вариант «только B» ломает B=0,C=n и длины >255)
- [ ] аудит флагов (`--audit`): DCX/djnz/сдвиги Z vs CY / `ld a,r`
- [ ] `OVERLAP`: заглушка **и** наведение всех ссылок; в lst нет `unused`
- [ ] `PIN`/`FIXED` если глифы/таблицы сидят в байтах кода или на границе
      страницы (бисект по CALLTRACE, не по числу замен)
- [ ] мёртвый код после врезок (`i8080_dead`) + негатив: профильные PC ⊆
      достижимых; SMC в «мёртвое» → `KEEP`
- [ ] `BYTE_TAB`, целящие внутрь развёрнутой команды → `OPERAND_PATCH`
- [ ] карта `labels.json` → `game_labels.inc` / `G()` для врезок и стендов
- [ ] гейты: `check_i8080` по **всему** образу; `block_equiv` Z80 vs i8080
      на границах итерации (+ плоскости); негативы `SKEW` / битый хелпер;
      «0 границ сверено» = провал
- [ ] то, что тикает по кадрам (пламя/пейсер-фаза) — честно исключить из
      block_equiv или выровнять, с негативным контролем
- [ ] playthrough редких веток (аналог «после шара»): PC ниже образа /
      вне зон — в каждом стенде

Критерий: тот же геймплей, что у эталона Z80; итерация укладывается в
пейсер (у Spirits было 1.57× тактов, пейсер всё ещё задавал темп).

### F. Железо и полный порт

- [ ] Emu80 + MiSTer (js прощает палитру и IRQ)
- [ ] заставка/меню Executive, справка по желанию
- [ ] замер `di`-кусков; палитра из гашения
- [ ] **потери кадровых прерываний (отложено 07.11, подумать).** В живой игре

      импульс прерывания живёт одну инструкцию, под DI он пропадает. Почти всё
      DI основного цикла — `TILE_BAND_FILL` (SP читает таблицу указателей
      плиток, ≈30k тактов/итер = 7% времени). Цена: пропущенный тик часов
      матча и музыки, копия зон на экран опаздывает на кадр (`DP_SYNC` ждёт
      дольше). Варианты:
      A — заливка без SP (таблица через HL, указатель плитки через
      push/pop): потери ≈0, памяти не надо, заливка в ~1,5 раза медленнее
      (до −3% темпа, часть вернётся за счёт неопаздывающей копии);
      B — оставить SP при EI, обработчик прерывания чинит 2–4 затёртых байта
      таблицы из копии: темп сохраняется, ~90 Б, сложно (старт на чужом
      стеке). Замер DI по процедурам — `prof_play` с подсчётом тактов при
      `!cpu.iff`, потерь — счётчик входов в `IRQ_HANDLER` против кадров
      (см. docs/frame-render.md, раздел о живой игре).
- [ ] ЧБ-вариант как эксперимент (идея 07.11): одна плоскость вместо 2+2 —
      подготовка, наложение и копия ~вдвое дешевле (≈ −20% тактов итерации);
      замерить против CPC (`tools/cpc_speed`, `tools/bench_play.js`).
- [x] Заставка CPC с анимацией (09.11): баскетболист крутит мяч — 24 шага по

      и DP_BUF 1B40..2215 (до игры они пусты; после пробела обнуляются).

## Гейты (минимум, с негативным контролем у каждого)

| гейт | ловит |
|---|---|
| round-trip disasm / v06 | сборка ≠ payload |
| карта чт/зп оригинала vs перенос | «не перенесли блок» |
| `trap_stale` | адреса в данных, исполнение в db |
| сверка состояния с MSX | логика при «красивой» картинке |
| `check_i8080` | оставшиеся DD/FD/ED/CB/jr |
| `block_equiv` + плоскости | ошибка развёртки/флагов/карты |
| playthrough / матч целиком | поздние ветки, OVERLAP |
| пара образ↔ядро в стендах | Z80-ROM на i8080-ядре |

Адреса в стендах — только из карты/`G()`, не литералы Z80.

## Критерий «играбельно»

1. Меню Executive → матч 1P и 2P на i8080-образе.
2. 2+2: читаемые 4 пера, без «ZX ink».
3. `block_equiv` 0 расхождений на планке итераций; негативы краснеют.
4. Нет stale, нет срыва PC; на MiSTer нет полосы палитры.

## Не цель первой волны

Пиксель-перфект CPC; AY-parity; DOS; схема Spirits «Exolon»/«2+1» как
основная (здесь сознательно 2+2 под CPC).
