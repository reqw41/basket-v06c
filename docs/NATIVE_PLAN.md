# Нативная логика i8080 и звук как в Bruce Lee (план, 09.11)

Решение владельца 09.11: **вся логика игры** переписывается вручную под i8080 по
схеме indy-v06c (Z80 → JS-модель → i8080), выполняю сам. Звук — как в
brucelee-v06c. Каждый этап — коммит; без пройденных ворот дальше не идём.
Гейты `verify_refactor --profile full` зелёные на каждом коммите.

## Зачем

- Темп: логика (переведённый код + помощники `il_*`) стоит ~77k тактов на ход
  из ~446k (17%, `prof_play`, 09.11); тот же код на Z80 втрое дешевле. Ручной
  i8080 по модели — цель ≤ 40k, то есть ход быстрее на ~8% (≈ темп CPC 7,5).
- Память: сейчас код игры после перевода 11,8 КБ + помощники 0,7 КБ, запас 156 Б.
  Ручной код меньше — освободившееся идёт под ускорения вывода и звук.

## Дорожка A — логика

### A0. Опись и эталоны
- Опись окна игры 84D0..B257 и системного блока 3300..3F7F (переезд D-блока
  MSX): процедуры, граф вызовов, что логика, что платформа (вызовы адаптера:
  COLOR_SPRITE, печать, звук, ввод, публикация). Файл `docs/native/INVENTORY.md`.
- Эталоны с Z80-образа порта (он равен MSX ход в ход, `msx_lockstep`):
  сценарии 1P/2P, три уровня, смена имён, фолы, аут, двойное ведение,
  возврат, трёхочковые, повтор, конец таймов, итоги. На каждый ход: состояние
  до (рабочие ячейки 4000..4159, данные окна, системный блок), ввод, состояние
  после, журнал вызовов адаптера с аргументами и звуковые запросы.
  `tools/native/golden.js` → `research/golden/*.json.gz` (не в git, пересобираются).
- Покрытие: каждая команда Z80 окна исполнена хотя бы в одном сценарии (или
  записана как мёртвая с причиной).
- **Ворота A0:** покрытие 100% живого кода; эталоны детерминированы (два
  прогона — одинаковые файлы).

Состояние A0 (09.11):
- Опись готова: 221 процедура, 9307 байт (`tools/native/inventory.py`).
- Эталоны: `tools/native/golden.js`, все сценарии — `tools/native/golden_all.sh`.
  Пишется каждый переход логика ↔ платформа: регистры и изменённые байты ниже C000.
  Прерывание кадра откладывается до кода платформы. Ожиданиями считаются HALT и
  задержка 3A4A (`cfg/native_waits.json`). Поэтому участок логики между двумя
  событиями — чистая функция памяти, и модель может повторить его байт в байт.
- Один шаг сценария — один кадр ТВ (`oneInterrupt`). `oneFrame` в vector06js
  пропускает кадры по настенным часам, и прогоны выходят разными; это касается
  и старых стендов на `oneFrame`.
- Два прогона дают побайтно одинаковые файлы.
- Покрытие 94,6% (`docs/native/COVERAGE.md`): 23 сценария, в том числе
  найденные поиском (`tools/native/golden_search.js`: случайные матчи с
  ботами mix/mix2, запуск только покрытия).
- Мёртвый и недостижимый код записан с причинами в `cfg/native_dead.json`
  (178 команд).
- Осталось 50 команд в 13 процедурах. Почти все — варианты событий с битом 0
  в (ix+1) игрока: размещение мяча, повтор, трёхочковые зоны, фол
  пятым у игрока 1. Случайная игра до них не доходит.
- Решение: эти ветки закрываются в A1 синтетическими снимками. Процедура
  исполняется на Z80 из эталонного состояния с подставленными полями игрока и
  сверяется с моделью. Условия веток выясняются при написании модели.
  Ворота A0 считаю пройденными, кроме этих 50 команд — они переходят в
  ворота A1.

### A1. JS-модель
- `src/model/*.js` — логика игры по модулям, состояние — массив 64 КБ в
  раскладке порта (адреса те же), вызовы адаптера — в журнал.
- `tools/native/model_run.js`: для каждого хода каждого эталона — модель от
  «состояния до» и ввода даёт «состояние после» и журнал **байт в байт**.
- **Ворота A1:** все сценарии, все ходы, без исключений (кроме перечисленных
  с причиной: счётчики кадров, часы по прерыванию).

Состояние A1 (09.11): **ворота пройдены.**
- Модель: `src/model/` — 22 модуля, ~4000 строк, 228 точек входа (все
  процедуры описи, заглушки-переходы векторных таблиц, AE19). Флаги Z80
  воспроизводятся точно (`z80.js` повторяет ядро vector06js), регистры и стек
  — как у Z80 в каждой точке выхода в платформу. Описание — `src/model/README.md`.
- `STRICT=1 node tools/native/model_run.js`: 25/25 эталонов, ядро Z80 не
  исполнило ни одной команды (вся логика — JS); сверка в каждом событии:
  регистры (без F), записанные байты, байты эталона; ~3 с на все эталоны.
- `SHADOW=1`: каждый вызов JS-процедуры без выхода в платформу повторяется на
  Z80 из того же состояния, сравниваются все регистры с F и память — 25/25.
- `node tools/native/model_fuzz.js 30 7`: снимки входов из эталонов, мутации
  полей игроков, мяча и матча, точные случаи для редких ветвей; каждая
  процедура исполняется на Z80 и в JS с одинаковыми заглушками платформы
  (журнал вызовов с регистрами). 23 365 прогонов, расхождений 0; все 47 команд,
  которых не исполнил ни один эталон, достигнуты. Ещё 2 участка записаны
  мёртвыми с причиной (9E0B..9E0F, 88C4 — `cfg/native_dead.json`).
- Стенд (`tools/native/machine.js`) по ходу научился: возврат платформы в вызов
  модели (метка-адрес возврата, по слову эталонного стека), IRQ из HALT с
  возвратом прямо в код игры, вход платформы в игру переходом JP, возвраты
  платформы «через кадр» (063F → 370B, 0903/08DE в повторе) — раскрутка
  JS-кадров исключением `Unwind` по SP.
- Рекордер эталонов: брошенные кадры ISR после HALT больше не превращают
  обычные вызовы в «выход из входа» (эталоны перезаписаны).

### A2. i8080 по модулям
- `src/native/*.asm`, только команды i8080, раскладка памяти та же. Модуль за
  модулем подменяет переведённые процедуры (гибридная сборка: остальное ещё
  из `recompile_i8080`).
- Сверка модуля: `tools/native/unit.js` — процедура на ядре i8080 против
  модели на тех же входах (снимки из эталонов) + `block_equiv`, `msx_lockstep`,
  `frame_predict_i8080`.
- Порядок — по тактам (профиль): ИИ (86A2..), движение игроков и мяча,
  касания/отбор, броски и корзины, судейство, табло, потом меню, повтор, итоги.
- **Ворота A2 (на каждый модуль):** unit против модели на всех снимках;
  verify зелёный; такты модуля не хуже переведённого.

Состояние A2 (10.11): 11 модулей, вся игровая механика матча.
- Сборка: `cfg/native_modules.json` (участки Z80, входы, договор `out`,
  снимки `from`, ячейки `cells`/`smcw` для самомодифицируемых операндов) —
  `tools/recompile_i8080.py` не переводит эти участки, вставляет
  `src/native/<модуль>.asm` (синтаксис Z80, только команды i8080; по команде
  на единицу раскладки). `NATIVE=0` — выпущенный образ байт в байт,
  `NATIVE=a,b` — только эти модули.
- Сверка: `node tools/native/unit.js <модуль>` — i8080 против JS-модели со
  снимков эталонов и мутаций: выходы по договору, вся память данных, вызовы
  платформы с её входными регистрами (`cfg/platform_args.json`, по коду
  адаптера). `tools/native/gate_a2.sh` — все модули + run_i8080, block_equiv
  (у модулей — договор, прочее через ручной код — только память), frame_predict,
  msx_lockstep, bench_play (та же сцена, что у выпущенного образа).
- Модули: contact (8CF7), walk (9C7C..), stamina (9E82.., часы), pdraw
  (958F..98B2, 9E6F), sched (94B0..958E), action (8E5A..91B4), ai (869C..8A22),
  ball (8A23..8CF6), isr (36F3.., 3811.., A186), move (98B3..9A1A), flight
  (9A1B..9C7B).
- Итог: логика 76k → ~28k тактов на ход; ход 444k → 385k (bench_play, та же
  сцена), темп 6,75 → 7,78; запас кода 156 → 1323 байт. Все ворота зелёные.
- Попутно: run_i8080 и bench_play шли по секундомеру (`oneFrame`) — теперь по
  кадру ТВ; bench_play фиксирует зерно матча (0055): иначе более быстрая
  сборка приходит в матч на прерывание раньше и играет другой матч.
- Осталось переведённым: печать и табло (9F9A..A1A9, 3B53), меню, итоги,
  повтор, звук (AA7C..AC04 — уйдёт с дорожкой B), системный блок (старт,
  ввод строки, 3732..), главный цикл (84E8..8695), рестарты (91B5..92A6),
  386E/388A/398C/39A3.

## Дорожка B — звук как в brucelee-v06c

Сейчас: игра пишет регистры AY в тень (V_AYREG), прерывание каждый кадр
переводит их в три счётчика ВИ53 (громкость ≥ 6), музыка — переведённый плеер
игры (MUSIC_TICK), шум — динамик в ожидании кадра (NOISE_WAIT), однобитные
щелчки — BIOS CHGSND через бипер.

Как в Bruce Lee (`src/vec/sound.asm`, `tools/mkcpcsnd.py` там):
- музыка и эффекты CPC заранее пересчитаны инструментом (модель очереди
  звука прошивки CPC: огибающие, встречи каналов) в покадровые таблицы 50 Гц:
  делитель ВИ53 = 24 × период AY, длительность; громкости нет — нота звучит,
  пока огибающая ≥ 4;
- ВИ53: счётчик 0 — часы, счётчик 1 — голос 1, счётчик 2 — голос 2;
- шум — случайные биты на динамик (ВВ55 порт C, Галуа 16): вспышка в
  прерывании и в простое;
- проигрыватель — в прерывании, игра на время звука не стоит.

Шаги:
- B0. Опись звука Basket: какие эффекты и мелодии у CPC (данные
  `src/assets/cpc_snd_ay.bin`, 7AE8..7FB9), откуда их зовёт логика, как
  звучит сейчас (запись WAV эталона CPC и порта).
- B1. `tools/mkcpcsnd.py` для Basket (по образцу Bruce Lee) → таблицы.
- B2. Проигрыватель в прерывании вместо тени AY и MUSIC_TICK; звуковые
  запросы логики — в очередь проигрывателя (в нативной логике — прямо).
- **Ворота B:** на слух владельца + сравнение спектрограмм с CPC.

Порядок: A0 → A1 → A2 (по модулям) → A3; B идёт, когда A2 освободит память
(таблицы звука больше данных AY), или раньше, если хватит места.
