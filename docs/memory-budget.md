# Бюджет памяти (этап 1)

Целевая карта из [refactor-plan.md](refactor-plan.md) проверена как
**бюджетная декларация**, не как уже внедрённая раскладка.
Рабочий ROM остаётся на MSX-адресах; `memory_layout: NOT_CHECKED`.

Декларация привязана к текущему ROM:
`191d127837def0664378cba37b0fc32f040d0c999bef258be6513c2c41f1079e`.

Машинная проверка: `cfg/memory_budget.json` +
`python3 tools/memory_budget_v06.py` (регрессии
`tools/test_memory_budget_v06.py`). Статус декларации: **MEASURED_DEFICIT**, evidence **INCOMPLETE**.
Текущий образ полностью классифицирован отдельным контрактом
`cfg/current_memory_map.json`; его отчёт строит
`tools/classify_memory_v06.py`. Несжатые ресурсы превышают целевой лимит;
формат цвета, декодер и рост 8080 пока не доказаны.

## 2. Бюджет кода

Текущих данных недостаточно для утверждения, что код помещается с запасом.

| Граница оценки | Байты | Что доказано |
|---|---:|---|
| Наблюдаемый нижний предел | 13284 | adapter 2016 + CFG game 9971 + CFG system/HUD 1297 |
| Верх по занятым кодовым областям | 16868 | adapter 2016 + всё окно game 11656 + весь system/HUD-span 3196 |
| Ёмкость | 15872 | `0200..3FFF` |
| Диапазон результата | **−997…+2620** | зависит от точной классификации и выноса данных |

Перенесённый `3304..3F7F` больше не делится фиктивно на два непрерывных куска. Текущий
отчёт отмечает точные позиции 1344 байтов CFG/SMC-кода, 329 байтов
наблюдаемого state/data и 1603 байта `opaque retained`. Последний класс занят
и сохраняется, но ещё не назначен будущей секции code/resources/state.

### Запас под 8080

`tools/exp_8080_growth.py` теперь публикует только размеры синтаксических
эскизов. Они не сохраняют все регистры и флаги и потому не являются
эквивалентными заменами. Ранее указанная оценка `+1800…4200` отозвана.
Резерв `4000..4FFF` = 4096 байт остаётся пустым, но его достаточность имеет
статус **UNPROVEN** до перекомпиляции репрезентативных процедур и сравнения
состояния CPU/памяти на одинаковых входах.

### Эксперимент упаковки (`tools/exp_pack_resources.py`)

Точный round-trip на реальных срезах ROM:

| Срез | raw | RLE | zlib |
|---|---:|---:|---:|
| menu slot | 2880 | 2249 | 1111 |
| court | 3584 | 2450 | 1279 |
| stamp | 352 | 323 | 339 |

| music | 1053 | 1056 | 419 |

| **сумма** | 23715 | **21126** | — |

- Семь RLE-потоков с terminator занимают **21133 байта**, дефицит **653 байта** в resources. Прямой декодер находится в code и проходит Z80 round-trip test. Menu и HUD уже используют его в рабочем ROM; остальные потоки пока остаются бюджетным экспериментом.
- zlib остаётся только host reference; целевого декодера для него нет.
- Dual-plane ×2 от RLE: ~40.8 КБ — **не влезает**.
- Предпочтительный цвет: **1-бит + атрибуты при publish**
  ([v06-planes-2plus2.md](v06-planes-2plus2.md)), тогда упакованный
  объём близок к mono, не к ×2.

Предполагаемый формат спрайтов: 2 цветовых слоя **или** 1-бит + attr;
маска прозрачности как сейчас; сдвиги — варианты полос/таблиц на этапе 5.

## 4. Графические буферы 3 КБ

Полноэкранный COMPOSE и 3.5K title snapshot удалены. Один буфер
`2000..24FF` переиспользуется по времени: меню занимает 1280 байт (32×40),
а zoom replay — 960 байт (16×60). За ним размещены корт `2500..32FF`,
указатели `3300..3303` и перенесённый system/HUD `3304..3F7F`.

### Реализованная схема

Матч и меню сначала преобразуют CPC-спрайты в общий staged-буфер
`B498..BBFF`, оставляя предыдущий полный кадр на экране. В конце логического
кадра старые dirty rectangles восстанавливаются, а готовые спрайты выводятся
в `E000`/`C000` с синхронизацией по vblank. Zoom replay переиспользует тот же
буфер и копирует обе плоскости выбранной половины 16×60 в `2000..23BF` и
`B498..BBFF`; HUD ниже y=120 не перерисовывается.

### Пиковая одновременная занятость

| Режим | Оценка | Обоснование |
|---|---:|---|
| Матч | 1896 | staged stream; dirty lists входят в state |
| Меню | 3176 | background band 32×40 + staged stream |
| Повтор | 1920 | две staging-плоскости по 16×60; HUD остаётся на экране |
| Переходы | 3176 | тот же набор menu + staged buffers |

Буферы повтора разделены по двум уже классифицированным графическим областям.
`C000..DFFF` активен как вторая видеоплоскость. **Отсутствие мерцания размером не доказывается** и
остаётся пунктом ручной проверки на железе/эмуляторе.

## 5. Состояние и стек

**State ~2091 / 3072:** replay workspace 1216, adapter `0F00` 256, keys 346,
DIRTY_OLD 109, pointers 4 и оценка match-vars 160. Ориентировочный запас —
981 байт; новые трассы могут уточнить mixed state.

**Стек `BC00..BFFF`:** `tools/exp_stack_depth.js` на пути title→menu→1P ready:

- min SP = `BFC2`, depth = **62** байта
- текущий регион 1024, запас **962 байта** на этом пути
- не проверено: natural replay, ESC→menu, 2P, глубокая вложенность IRQ
- SP-рисование (`bench_sp_copy`) **не** должно забирать бюджет стека

## 7. Заключение о вместимости

| Бюджет | Вердикт |
|---|---|
| Sys / planes | Подтверждены |
| Code (Z80) | **Не доказан**: диапазон −997…+2620; требуется точный split D/game |
| Reserves | Пусты (как требуется) |
| State / stack | Укладываются с оговорками по покрытию сценариев |
| Gfx buffers | Реализованы: peak 1280 / 3072; визуальная приёмка на железе остаётся |
| Resources | Raw-дефицит 3235; RLE сокращает его до 653 байт, runtime integration остальных потоков ещё не готова |

**Можно продолжать по принятой карте**, если этапы 4–5 явно включают:

1. подключение RLE к реальным потребителям без постоянной распакованной копии;
2. компактное кодирование или генерацию color attributes;
3. сохранение обоих резервов свободными;
4. обновление адресных контрактов вместе с переносами.

Карта пока имеет статус **UNPROVEN**: raw-ресурсы превышают лимит на 3235
байт. Экспериментальный RLE сокращает дефицит до 653 байт;
on-demand распаковка пока подключена только для меню и HUD. Назначенные
объекты Z80-кода оставляют 661 байт, без окончательного split mixed D-region.
